# NOVA Secure Conversation Bridge

This service is the browser-to-Pi conversation gateway for NOVA Voice.

It deliberately supports **conversation + TTS only**. It does not expose shell commands, GPIO, file writes, messaging or account actions to the public website.

## Flow

`voice.universaldragon.com -> NOVA Bridge (8130) -> LLM brain -> Voice Soul v3 (8125) -> WAV reply`

## Security model

- Binds to `127.0.0.1` by default.
- Intended to sit behind a Cloudflare Tunnel + Cloudflare Access policy before any public exposure.
- Browser requests are limited to `NOVA_ALLOWED_ORIGINS`.
- No API keys or bearer tokens are stored in website JavaScript.
- When `NOVA_REQUIRE_CF_ACCESS=1` (default), browser requests must arrive with Cloudflare Access identity headers. A separate `NOVA_BRIDGE_TOKEN` can be used for trusted non-browser clients.
- The bridge reports `executed_action: false` for every chat request.

## Pi 5 install path

Checkout the review branch first:

```bash
cd ~/universal-dragon-voice-core
git fetch origin
git switch nova-voice-soul-v3
git pull --ff-only
```

Install the bridge as a user service without starting it:

```bash
cd ~/universal-dragon-voice-core/nova_bridge
chmod +x install-user-service.sh check-config.sh
./install-user-service.sh
```

The installer creates the virtual environment, installs bridge dependencies, copies the systemd user unit, and creates a private local env file if one does not already exist. It intentionally does **not** start the service until configuration is validated.

## Required environment

Local secrets live in:

```text
~/.config/universal-dragon/nova-bridge.env
```

Never commit that real env file.

At least one brain provider must be configured there. Voice Soul v3 defaults to:

```text
NOVA_VOICE_URL=http://127.0.0.1:8125
```

Allowed website origins should include the production site and the WebsitePublisher preview while testing:

```text
https://voice.universaldragon.com
https://project28268.websitepublisher.ai
```

For production, keep:

```text
NOVA_REQUIRE_CF_ACCESS=1
```

For local-only testing before Cloudflare Access is configured, it may temporarily be set to `0`; trusted non-browser tests should use `NOVA_BRIDGE_TOKEN`. Do **not** place `NOVA_BRIDGE_TOKEN`, provider keys, or `NOVA_VOICE_TOKEN` in public website JavaScript.

## Validate and start

Validate without displaying secrets:

```bash
cd ~/universal-dragon-voice-core/nova_bridge
./check-config.sh
```

Then start only after the check passes:

```bash
systemctl --user enable --now nova-bridge.service
systemctl --user status nova-bridge.service --no-pager
curl http://127.0.0.1:8130/healthz
```

Optional end-to-end local smoke test:

```bash
set -a
source ~/.config/universal-dragon/nova-bridge.env
set +a
python3 ~/universal-dragon-voice-core/nova_bridge/smoke_test.py
```

The smoke test confirms the conversation-only safety boundary, obtains one brain response, and reports whether Voice Soul v3 produced audio. It does not execute commands or hardware actions.

## API

### `POST /v1/chat`

```json
{
  "text": "NOVA, short-aa hello sollunga",
  "session_id": "optional-browser-session-id",
  "language": "auto",
  "mood": "auto"
}
```

Response includes the text reply, brain provider, optional short-lived WAV URL, voice metadata, and:

```json
{
  "executed_action": false
}
```

### `GET /v1/audio/<id>.wav`

Short-lived WAV generated by Voice Soul v3. The browser fetches the audio through the same authenticated bridge origin and plays it as a Blob URL.

## Production boundary

Before connecting the public site:

1. Voice Soul v3 remains private on localhost.
2. NOVA Bridge remains private on localhost and is published only through an authenticated tunnel.
3. Cloudflare Access is enforced for the bridge hostname.
4. Allowed origins are verified.
5. No action/tool endpoints are exposed through this bridge.
6. A local smoke test passes before the website is pointed at the production bridge URL.

A future permission-gated action service should remain a separate component with explicit approval + verification, rather than being added to this conversation endpoint.

## Current verification status

The code is on the draft `nova-voice-soul-v3` branch. The public website is bridge-ready, but Pi deployment, Voice Soul runtime success, Cloudflare Access, and end-to-end browser audio remain **unverified until run on the real Pi/inference host**.
